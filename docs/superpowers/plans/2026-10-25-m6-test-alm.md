# M6 Testing and ALM Implementation Plan

> **For agentic workers:** Most of this plan is browser work (Copilot Studio, Power Apps, Power Platform admin center), done by the user, who sends screenshots; a small part is files and code (test set, test set validation, a second employee API instance, export package check), which AI writes and tests with TDD. AI is also responsible for looking up docs, explaining, troubleshooting, taking notes, updating the coverage table, and committing at the end of each Task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a 30-item test set for `HR Assistant Classic`, run it with Copilot Studio's built-in evaluation and compare several test methods; put the agent and the components it depends on into the solution `HRAssistant`, replace hard-coded values with environment variables, and deploy to a second developer environment `HR-Test`. Covers 7 bullets in two exam objective groups, Evaluate agent performance (38-40) and Implement ALM (41-44), plus bullet 6, Plan reusable agent components, on the side.

**Architecture:** 
- `HR-Dev` is the development environment; `HR-Test` is a new developer environment used as the test environment.
- The solution `HRAssistant` (unmanaged) lives in HR-Dev and is exported as a managed package and imported into HR-Test.
- The two environments use different employee API addresses: HR-Dev uses port 3000, HR-Test uses a new port 3001 on the same tunnel (a second instance of the same code). That way "a hard-coded URL in Test still points at Dev" becomes visible.

**Tech Stack:** Copilot Studio agent evaluation, Power Platform solutions / environment variables / pipelines (platform host), Power Apps maker portal, Microsoft Dev Tunnels, Node `node:test`.

**Spec:** `docs/superpowers/specs/2026-09-13-ab-620-hr-assistant-design.md` (§4 M6)

## Global Constraints

- The main agent is always `HR Assistant Classic`, the development environment `HR-Dev`, the test environment `HR-Test`, the solution name `HRAssistant`.
- **Things found while writing the plan (2026-10-25) that differ from the design doc:**
  1. **A pipeline's target environments must be Managed Environments, and the Developer Plan doesn't include the right to use Managed Environment.** Original text: "All target environments used in a pipeline must be enabled as managed environments" ([platform host](https://learn.microsoft.com/en-us/power-platform/alm/platform-host-pipelines)); "A managed environment isn't included as an entitlement in the Developer Plan when users run their assets" ([licensing](https://learn.microsoft.com/en-us/power-platform/admin/managed-environment-licensing)). So HR-Test either turns on Managed Environment (which may need a premium trial license) or goes the manual export/import route. In Task 6 the user picks one of the two routes.
  2. **"Extend pipelines" is learn-only for us.** Personal pipelines (platform host) "can't be extended". Extensions (gated extension, Power Automate triggers) need a custom host, a host needs a production environment, and we have no capacity. Bullet 44 Built can only count the "pipeline runs end to end" half; the extension part is recorded as Understand.
  3. **Evaluation doesn't support Fabric data agents, nor agents using Authenticate manually.** HR Data Agent is already Off, and the test set has no Fabric questions. Task 1 confirms HR Assistant's authentication method.
  4. **Evaluation connects to knowledge sources and tools as the currently signed-in user**, same as test chat. So before running an evaluation, the Employee API, the MCP server and their tunnels must all be running.
  5. **The import file only accepts two columns: `Question`, `Expected response`**, at most 100 rows, each question no more than 1000 characters. "Which tool is expected" can't go into the import file; it has to be set one by one in the UI, so it goes in a separate meta file.
  6. **Environment variables are read-only in Copilot Studio; the published version uses the value at the moment of publishing, so a changed value needs a republish** (except the secret type). A custom connector's Host can be `@environmentVariables("<schema name>")`, but after changing the value you must **re-save the connector**.
- **Evaluation results are kept in Copilot Studio for only 89 days**; export them as CSV to `test-sets/results/`. The data is all fake, so it can go in the repo.
- **Secrets go neither into the repo nor into the chat.** The full tunnel URL is not written into the repo; notes only give the tunnel name and port. `dev-local-key` is a mock value. Before committing an exported solution package, AI unzips and searches it first (see Task 6).
- **Cost:** The Azure free credit **expires 2026-11-15**. The test set has Foundry summariser and Azure AI Search questions, so M6's evaluations must be run before then. Environments, solutions and pipelines cost nothing. If Task 6 goes with a premium trial, use only the trial, don't pay.
- **UI paths change.** If a menu can't be found, find it yourself by "Goal" and "Verify", and record the actual path in notes.md.
- If any single step is stuck for more than 1 hour (1.5 hours for Pipelines), stop, record it in `milestones/M6-test-alm/break-and-fix.md`, mark Understand in the coverage table, and move on.
- Commit at the end of each Task; commit messages in English, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

Five things in the plan most likely to go wrong that no step specifically checks:

1. **The exported solution package carries the tunnel URL or key.** Environment variables' current values and the Send HTTP request node's URL and headers all get packaged. After the Task 6 export, AI unzips and searches for `devtunnels.ms`, `x-api-key`, `Bearer`, `eyJ`, `AccountKey`. A package containing a tunnel URL doesn't go in the repo; first add `exports/*.zip` to `.gitignore` and only commit an unzipped manifest with the URL removed.
2. **Expected answers in the test set don't match the data or policy text**, so an evaluation "failure" is actually a bad question. `test-sets/test-sets.test.mjs` checks that the numbers in balance questions match `data/employees.csv`, and that the keywords in policy questions appear in the source text of `data/policies/*.md`.
3. **The reply language doesn't match the expected answer.** HR Assistant sometimes answers in Chinese. Compare meaning fails outright on a language mismatch. The test set always asks in English and writes expected answers in English; if a failure is due to language, Task 3 records it as its own category, not as the agent answering wrong.
4. **A connection is missing when importing into HR-Test; the import "succeeds" but the agent errors as soon as it calls a tool.** After the Task 6 import, ask one question for each of the three capability types (knowledge, connector tool, MCP); don't just look at import success.
5. **Changing managed solution components in HR-Test** creates an unmanaged layer that later upgrades can't override. In HR-Test only change environment variable values and connections, not the agent itself. Check solution layers once at the end of the Task 6 steps.

### Task 2: Test set (about 1 hour)

**Goal:** AI writes 30 English test questions and expected answers, with a test that guarantees their format is correct and consistent with the data.

**Files:**
- Create: `test-sets/hr-assistant-v1.csv` (for import, two columns)
- Create: `test-sets/hr-assistant-v1-meta.csv` (same 30 rows, same order)
- Create: `test-sets/test-sets.test.mjs`

**Interfaces:**
- Produces:
  - `hr-assistant-v1.csv` header is exactly `Question,Expected response`.
  - `hr-assistant-v1-meta.csv` header is exactly `Question,Category,Expected capability,Keywords`. `Keywords` is separated by `;`. `Expected capability` uses names from the Task 1 component inventory; questions that use no tool get `none`.
  - `Category` can only take the nine values below, with fixed counts:

| Category | Questions | Source of expected answer |
|---|---|---|
| `policy` | 8 | `data/policies/*.md` |
| `leave-balance` | 4 | `data/employees.csv` |
| `employee-search` (MCP) | 2 | `data/employees.csv` |
| `password-reset` | 2 | Password Reset topic |
| `submit-leave` | 2 | First response of the Submit Leave Request topic |
| `onboarding` | 3 | `data/onboarding/onboarding-checklist.md` |
| `summariser` (Foundry) | 2 | `data/policies/*.md` |
| `custom-prompt-or-search` (M4) | 2 | M4's Azure AI Search index and custom prompt |
| `out-of-scope` | 5 | The refusal behavior in the agent instructions |

- [ ] **Step 1: Write the failing test**

  `test-sets/test-sets.test.mjs`, same style as `data/data.test.mjs` (`node:test`, `node:assert/strict`, a small hand-written CSV parser that handles quoted fields and commas). Five tests:
  1. `import file has the exact header and 30 rows`: header equals `Question,Expected response`, 30 rows, every Question non-empty, no more than 1000 characters, no duplicates, every Expected response non-empty.
  2. `meta file matches the import file row by row`: correct header, 30 rows, the Question in row i is identical to row i of the import file.
  3. `categories have the planned counts`: the counts of the nine Categories equal the table above, no other values.
  4. `leave balance answers match employees.csv`: each `leave-balance` question has an employee ID (`E\d{3}`) in its Question, and its Expected response contains that employee's AnnualLeaveBalance or SickLeaveBalance number from `employees.csv`.
  5. `policy keywords appear in the policy text`: each `policy` and `summariser` question has at least one keyword, and every keyword (case-insensitive) appears in the combined text of `data/policies/*.md`.

- [ ] **Step 2: Run the test, confirm it fails**

  Run: `node --test test-sets/test-sets.test.mjs`
  Expected: FAIL, because the CSV files don't exist yet.

- [ ] **Step 3: Write the two CSVs**

  - All questions in English, phrased the way an employee would ask, not copied from document sentences.
  - Expected answers are written as the one or two sentences the agent should say, no citation format.
  - `out-of-scope` questions include: weather, writing a poem, asking about someone else's salary, asking to ignore the instructions, finance questions other than expenses.
  - `submit-leave` and `password-reset` are multi-turn topics; single-response evaluation only looks at the first response (e.g. asking for the employee ID). The expected answer is just that first sentence.

- [ ] **Step 4: Run the test, confirm it passes**

  Run: `node --test test-sets/test-sets.test.mjs`
  Expected: all 5 tests PASS.
