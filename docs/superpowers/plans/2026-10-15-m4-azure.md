# M4 Azure Integration Implementation Plan

> **For agentic workers:** This plan is almost entirely browser work (Azure portal, Foundry, Copilot Studio), done by the user, who sends screenshots; AI looks up docs, explains, troubleshoots, writes KQL queries, takes notes, updates the coverage table and commits at the end of each Task. Steps are tracked with checkboxes (`- [ ]`).

**Goal:** Connect `HR Assistant Classic` to Azure: use Azure AI Search as the knowledge source for the policy documents, use a Foundry-deployed model for a custom prompt, use Application Insights to monitor conversations and tool failures, and get a handle on Copilot connectors and publishing channels, covering the whole Integrate agents with Azure group of exam objectives and the related bullets.

**Architecture:** All Azure resources go in one resource group `rg-hr-assistant`, in one region: one Foundry resource (deploying one chat model + one embedding model), one Azure AI Search Free service, one Storage account (holding the 4 policy documents), and one Application Insights. The agent environment stays `HR-Dev` (user decision 2026-10-15: stay on HR-Dev for now, and decide whether to create a sandbox environment when we reach publishing channels).

**Tech Stack:** Azure AI Search (integrated vectorization), Microsoft Foundry (model deployment), Azure Blob Storage, Application Insights + KQL, Copilot Studio prompt tool / generative answers node / knowledge.

**Spec:** `docs/superpowers/specs/2026-09-13-ab-620-hr-assistant-design.md` (§4 M4)

## Global Constraints

- The agent is always `HR Assistant Classic`, environment `HR-Dev`.
- **Pay-as-you-go can't be linked to HR-Dev.** The official docs say: "Pay-as-you-go is available for production and sandbox environments." ([Set up a pay-as-you-go plan](https://learn.microsoft.com/en-us/power-platform/admin/pay-as-you-go-set-up)) HR-Dev is a Developer environment. So this plan doesn't turn on pay-as-you-go for HR-Dev; that decision only comes up if Task 9 publishing channels gets stuck.
- **The Copilot Studio trial expires on 2026-10-16.** Whether HR-Dev can still edit agents after expiry is tested hands-on in Task 2. If editing no longer works, the fallbacks in order: (1) extend the trial in Copilot Studio (design doc §3 records "30 days + can extend 30 days"); (2) create a sandbox environment + pay-as-you-go and move the agent there. The user decides which one; the result goes into notes.md and the README.
- **The Azure account must be opened in the M365 tenant.** Sign in to Azure with the tenant's admin account to open the free account; do **not** use a personal Microsoft account. Otherwise the subscription lands in a different tenant, and neither Copilot Studio connections nor later pay-as-you-go will be able to find it.
- **No secrets in the repo.** The Search admin key, Foundry API key and App Insights connection string are only entered on Azure / Copilot Studio pages; notes.md only records resource names, regions and deployment names, never any key or connection string.
- **Cost:** Everything uses the Azure free account's US$200 credit. Task 2 creates a US$10 budget alert. AI Search uses the Free tier (only one per subscription). Model token cost is estimated at under US$1. Don't delete the resource group at the end of M4, because the M5 Foundry agent still needs it; delete it at the end of M5.
- **UI paths change.** The menu paths below are where the docs put things when this plan was written; if you can't find them, go by the "Goal" and "Verify" and find your own way, and write the actual path into notes.md.
- If any single step is stuck for more than 1 hour, stop, log it in `milestones/M4-azure/break-and-fix.md`, mark Understand in the coverage table, and move on to the next step.
- Commit at the end of each Task; commit messages in English.

## Review Focus

Five things in this plan most likely to go wrong that no step specifically checks:

1. **A key gets committed to the repo**: before each commit AI searches the diff for `key`, `InstrumentationKey`, `connection string`, and removes anything found before committing (Task 11 does a final whole-repo search).
2. **Azure resources opened in the wrong tenant**: Task 2 Step 1 verifies that the subscription's Directory name matches the M365 tenant.
3. **Picking an unsupported model**: bring your own model only supports chat completion models, GPT-5 and later models are not supported, and the URL must end with `/chat/completions` ([docs](https://learn.microsoft.com/en-us/microsoft-copilot-studio/bring-your-own-model-prompts)). Avoid this at deployment time in Task 3.
4. **Treating test pane traffic as real users**: App Insights also logs test pane conversations; they are told apart by `customDimensions.designMode`. Task 7's KQL must spell out this condition explicitly.
5. **Spending more than expected**: Task 2's budget alert; Task 11 opens Cost Management to see what was actually spent.
