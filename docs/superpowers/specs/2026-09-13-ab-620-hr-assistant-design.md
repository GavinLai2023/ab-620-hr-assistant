# AB-620 exam-prep main project design: HR Assistant

Date: 2026-09-13
Status: awaiting user review

## 1. Goals and principles

**Goal**: pass Microsoft Exam AB-620 "Designing and Building Integrated AI Solutions in Copilot Studio" and earn Microsoft Certified: AI Agent Builder Associate. The exam is taken in English.

**Means**: one HR Assistant project running from start to finish, doing every bullet of the official exam objectives hands-on.

**Four principles**

1. **Learning over product**. The project exists only to cover exam points and build understanding; it doesn't aim to be usable, pretty or production-ready. Mock data, mock APIs, no UI, no fine-grained permissions.
2. **The coverage table is the single source of truth for progress**. `docs/coverage.md` records each exam objective bullet in four columns, Understand / Built myself / Can explain / Exam ready, updated at the end of every milestone, never judged by gut feeling.
3. **The learning loop is fixed as**: Learn → build it myself → break it on purpose → Troubleshoot → record → back to Learn. Every milestone includes a "break it on purpose" step.
4. **Timebox and move on**. If any single feature is stuck for more than 1 hour, read the docs, write a note, mark Understand in the coverage table, and keep going.

**Constraints**: 7–8 hours a week; no fixed exam date; costs mainly free and trial, small amounts acceptable after the trials.

## 2. Project definition and repo structure

**Project name**: HR Assistant. Fictional company Contoso, about 20 employees.

**Business scenarios (only the minimal set the exam points need)**

| Scenario | Purpose | Exam points covered |
|---|---|---|
| HR policy Q&A | 4 policy documents on SharePoint | Knowledge, generative answers, Copilot connectors |
| Password reset guidance | Fixed process | Classic Topic, adaptive cards |
| Leave balance lookup | Calls a mock employee API | REST tool, custom connector, MCP |
| Leave request and cancellation | Needs manager approval | Agent flow, human-in-the-loop, error handling |
| Onboarding assistant | Handed off to a second Agent | Multi-Agent, Foundry agent, A2A |
| HR data Q&A | Department headcount, leave trends | Fabric data agent |

- SharePoint site "HR Policies": four documents (annual leave, sick leave, remote work, expenses), generated by Claude.
- Mock Employee API: a local Node.js service exposed at a public address via Microsoft Dev Tunnels, with data matching the Dataverse table.

## 3. Environment and cost strategy

**Overall principle**: stagger sign-ups; turn on each service one week before the milestone that actually needs it.

| Service | When to sign up | Plan | Cost | Purpose |
|---|---|---|---|---|
| Power Apps Developer Plan | M0 | Free, permanent | 0 | Dataverse developer environment; up to 3, M6's Dev / Test rely on it |
| Copilot Studio trial | M0 | 30 days + 30-day extension; after expiry agents keep running for 90 days | 0 | M1–M3 all done in the test pane. A trial license can't publish agents |
| Copilot Studio pay-as-you-go | Before M4 | Pay-as-you-go, linked to an Azure subscription | US$0.01 per credit, a few dollars a month at experiment scale | Unlocks publishing to Teams / M365 Copilot |
| Azure free account | One week before M4 | US$200 credit for 30 days, then upgrade to pay-as-you-go | 0 within 30 days, small amounts after | AI Search Free tier (50 MB, 3 indexes), Application Insights, Foundry |
| Microsoft Foundry | M4 | Comes with the Azure subscription | Models billed per token, estimated US$1–5 a month | Model catalog custom prompt, Foundry agent |
| Microsoft Fabric | M5 | 60-day free trial | 0 | Fabric data agent, done once only |
| Microsoft Dev Tunnels | M3 | Free | 0 | Expose the local mock API and MCP server to Copilot Studio |

SharePoint, Teams and Approvals use the existing M365 tenant.

**Cost ceiling**: estimated US$10–30 for the whole project. The README keeps a "services signed up and expiry dates" table, updated every milestone.

## 4. Milestone detailed design

Estimated 12–13 weeks, about 95–100 hours. The definition of "done" for each milestone: every exam objective bullet in the checklist is marked at least Understand, the hands-on ones are marked Built myself, the notes are written, and the coverage table is updated.

### M0 Environment setup (1 week, 6–8 hours)

- **Sign up**: Power Apps Developer Plan → create environment `HR-Dev`; Copilot Studio trial, record the expiry date; SharePoint site "HR Policies".
- **Prepare data**: Claude generates 4 policy documents and a 20-row employee CSV; import into the Dataverse `Employee` table.
- **Repo**: create the README, `docs/exam-outline.md`, and a first version of `docs/coverage.md` (all four columns empty for every bullet).
- **Learn**: read through the official study guide; Copilot Studio getting-started modules.
- **Acceptance**: can create an empty agent in Copilot Studio and hold a conversation in the test pane; can see the 20 employee rows in Dataverse.

### M1 HR policy Q&A Agent (1.5 weeks, 10–12 hours) — plan and configure

- **Learn**: official learning path "Design agent conversations and responses using topics in Microsoft Copilot Studio" (confirm the exact name during M0); 30 minutes of Dataverse basics; 30 minutes of Power Fx basics.
- **Lab 1**:
  1. Create agent "HR Assistant", with instructions written to six elements: scope, authority, grounding, privacy, fallback, output requirements.
  2. Knowledge: the SharePoint site, one public web page, the Dataverse `Employee` table.
  3. Three kinds of topic: password reset (fixed topic: question node, condition, message); leave balance (query Dataverse directly first, swap to a tool in M3); policy Q&A (a generative answers node inside a custom topic, with data sources and content moderation configured by hand).
  4. Response formatting: Markdown, citations, length limits.
  5. Variables: topic variables, global variables, System variables; Power Fx expressions such as `Text()`, `If()`, `System.User.DisplayName`.
- **Break it on purpose**: delete knowledge and see how answers change; remove scope from the instructions and ask unrelated questions; set content moderation to different levels and compare.
- **Acceptance**: all Configure topics bullets except those about agent flows, tools and APIs are Built; can explain without notes what problem knowledge, topics and tools each solve.

### M2 Leave request Agent flow (2 weeks, 12–14 hours) — plan and configure

- **Learn**: agent flows modules; Power Automate basics (trigger, action, connector); Approvals.
- **Lab 2**:
  1. Agent flow `SubmitLeaveRequest`: inputs EmployeeId, Type, StartDate, EndDate; writes to Dataverse `LeaveRequest`; outputs RequestId, Status.
  2. In the topic, use an adaptive card to collect dates and type, then another adaptive card to show the confirmation.
  3. Human-in-the-loop: the `CancelApprovedLeave` flow first sends an Approval to the manager, runs only if approved, and notifies the employee if rejected.
  4. Error handling: in the flow, use scope and "configure run after" to catch failures and return an error code to the topic; the topic gives fallback wording based on the error code.
  5. Monitoring: view the agent flow run history.
  6. Add the flow to the topic as a tool, and manage variable passing between topic and flow.
- **Break it on purpose**: pass an invalid EmployeeId; delete a Dataverse column so the write fails; approval timeout; flow returns an empty value. Record the agent's default reaction and the improved reaction.
- **Acceptance**: all Create and monitor agent flows bullets Built; in Configure topics, "Add agent flows to a topic", "Add tools to a topic", "Configure adaptive cards", "Manage variables" Built.

### M3 Tool integration (2 weeks, 14–16 hours) — integrate and extend

- **Learn**: official learning path "Integrate agents with enterprise systems in Microsoft Copilot Studio"; refresher on REST and OpenAPI basics.
- **Prerequisite**: Claude writes `src/employee-api` (Node.js, endpoints `GET /employees/{id}`, `GET /employees/{id}/leave`, `GET /employees?department=`, with an OpenAPI 3.0 definition and API key auth); expose it with Dev Tunnels.
- **Lab 3**:
  1. REST API tool: add it to the agent directly from the OpenAPI definition.
  2. Custom connector: in Power Apps maker, build a custom connector from the same OpenAPI file, then add it as a tool.
  3. "Send HTTP request" node: call the API directly in a topic and parse the JSON.
  4. MCP: Claude writes `src/mcp-server` (Streamable HTTP, tools: `search_employee`, `get_leave_balance`), connected to the agent via Dev Tunnels.
  5. Computer use: timeboxed to 1 hour, try to configure and monitor it; if unavailable, read the docs and take notes.
  6. Change M1's leave balance topic to call a tool.
  7. Identity notes: "whose identity the agent uses to access systems": no auth, API key, OAuth user delegation, service identity, and when each fits.
- **Break it on purpose**: API returns 500 or times out; make the description in the OpenAPI vague and watch the orchestrator pick the wrong tool; write an MCP tool description that overlaps with the REST tool; turn off the API key.
- **Acceptance**: all Add tools to agents bullets Built (computer use may be Understand); Connect to Microsoft Power Platform connectors Built; Configure advanced agent responses with API and Send HTTP requests Built; Configure advanced agent responses with custom prompts is filled in during M4.

### M4 Azure integration (2 weeks, 12–14 hours) — integrate and extend

- **Prerequisite**: open an Azure free account; switch Copilot Studio to pay-as-you-go and link it to the environment.
- **Learn**: Foundry modules; Copilot Studio docs on Azure AI Search and Application Insights.
- **Lab 4**:
  1. Azure AI Search Free tier: import the 4 policy documents to build an index; connect it as a knowledge source; switch generative answers to Azure AI Search with Foundry.
  2. Custom prompt: use an AI Builder prompt to pick a non-default model from the Foundry model catalog, build a "summarize the leave policy" prompt, and wire it into a topic.
  3. Application Insights: configure the connection string in the agent, run 20 conversations, and use KQL to query failed sessions, tool calls and latency.
  4. Copilot connectors: try connecting a Copilot connector as knowledge; if it needs an M365 Copilot license, timebox to 1 hour.
  5. Channels: publish to Teams, and to M365 Copilot if feasible; record the differences between channels.
- **Break it on purpose**: delete a field from the index; locate a deliberately caused tool failure in App Insights; swap between two models and compare output.
- **Acceptance**: all Integrate agents with Azure bullets Built; Connect to Azure AI Search and Connect to Copilot connectors Built or Understand; Plan channels and deployment Built.

### M5 Multi-Agent (1.5 weeks, 10–12 hours) — integrate and extend

- **Prerequisite**: start the Fabric trial.
- **Learn**: official learning path "Design and build multi-agent solutions in Microsoft Copilot Studio".
- **Lab 5**:
  1. Create a second Copilot Studio agent, "Onboarding Agent", connected to HR Assistant as a connected agent.
  2. Build an "HR Policy Summarizer" agent in Foundry and connect it to HR Assistant.
  3. A2A: connect Onboarding Agent via the A2A protocol (or connect an external A2A endpoint), and compare connected agent with A2A.
  4. Fabric: upload the employee and leave CSVs to a lakehouse, build a Fabric data agent, and connect it to HR Assistant to answer "which department takes the most leave".
  5. Design notes: who handles routing, context passing, permissions, errors, handoff.
- **Break it on purpose**: write overlapping descriptions for the two child agents and watch routing go wrong; revoke a child agent's access.
- **Acceptance**: all Configure multi-agent collaboration bullets Built (Fabric may be Understand).

### M6 Testing and ALM (1.5 weeks, 10–12 hours) — test and manage

- **Learn**: agent evaluation and ALM docs.
- **Lab 6**:
  1. Test set: `test-sets/hr-assistant-v1.csv`, 30 rows, with question and expected answer or expected tool; run it once with Copilot Studio's built-in evaluation.
  2. Evaluation methods: compare results from exact match, semantic similarity and AI grading, and record when each fits.
  3. Solution: create unmanaged solution `HRAssistant` and add the agent, flows, custom connector and environment variables to it.
  4. Environment variables: API base URL, SharePoint site URL; replace every hard-coded value.
  5. Create a second developer environment `HR-Test`; Power Platform Pipelines timeboxed to 1.5 hours; if not feasible, export and import by hand.
  6. Export the solution to `exports/`.
- **Break it on purpose**: leave one hard-coded URL, deploy to Test and watch it fail; deliberately leave out the custom connector and import again.
- **Acceptance**: all Test and manage agents bullets Built (Pipelines may be Understand).

### M7 Wrapping up the planning domain and exam prep (1 week, 8 hours)

- **Planning notes**: one page for each of the 7 Plan an agent solution bullets, using HR Assistant as the case: comparison of enterprise system integration methods (connector, REST, MCP, connected agent); identity strategy (user authentication, service identity, Entra, SSO); channel choice; responsible AI (content moderation, transparency, human oversight); security and governance (DLP, environment policies, sharing); reusable components (solution, component collections, connected agents); differences between internal and external audiences.
- **Scenario question self-test**: Claude writes 20 scenario questions; the user answers aloud and then checks against the explanations; anything unanswered is flagged red for remediation.
- **Exam prep**: run the Exam sandbox once; check whether the Practice Assessment is live (it wasn't as of 2026-09-13); check whether the AB-620T00 course is live, and if so use it as a systematic review; final audit of the coverage table.
- **Decide the exam date**: book as soon as the readiness criteria in section 7 are met.

## 6. Way of working

**Weekly rhythm**: on weekdays, 2 sessions of 1 hour each reading Learn and docs; on weekends, 5–6 hours of hands-on work, breaking things on purpose and writing notes.

**Fixed process for each milestone**

1. The user says "start M#", and Claude generates that milestone's lab steps, mock data and code (mock API, MCP server, test sets) according to this design.
2. The user does the hands-on work in Copilot Studio and Azure; Claude looks up docs, explains concepts and helps troubleshoot.
3. The user writes observations into `notes.md` and `break-and-fix.md`; Claude helps fill gaps, correct mistakes and standardize terminology.
4. End of milestone: tick `checklist.md`, update `docs/coverage.md`, update the environment expiry table in the README, git commit.

**Notes conventions**: each note tries to answer "what problem does this feature solve, and when should I not use it"; screenshots are not committed, only text is recorded.

**Timebox rule**: if a single feature is stuck for more than 1 hour (1.5 hours for Pipelines), stop, record it in `break-and-fix.md`, mark Understand in the coverage table, and move on.

## 7. Exam readiness criteria

Book the exam when all three of the following are met:

1. In `docs/coverage.md`, the Can explain column reaches 80% or more, and none of the three domains has an all-empty bullet.
2. Answer 16 or more of M7's 20 scenario questions correctly without notes.
3. Without notes, can clearly explain: the logic for choosing knowledge, topic or tool; the differences between REST tool, custom connector and MCP and when each fits; the difference between MCP and A2A; the relationship between a Copilot Studio agent and a Foundry agent; whose identity the agent uses to access systems; what problem solutions, environment variables and pipelines each solve.

## 8. Risks and fallbacks

| Risk | Fallback |
|---|---|
| Copilot Studio trial can only test, not publish | M1–M3 don't need publishing; switch to pay-as-you-go before M4 |
| Power Platform Pipelines requires the target environment to be a Managed Environment, which a developer environment may not satisfy | Manual solution export and import; the exam point is still covered |
| Computer use is unavailable under the current license | After a 1-hour timebox, switch to learning from the docs |
| Copilot connectors as a knowledge source need an M365 Copilot license | After a 1-hour timebox, switch to learning from the docs |
| Fabric trial sign-up doesn't go smoothly | Substitute docs and architecture diagrams; it's only one bullet |
| Azure US$200 credit expires after 30 days | Squeeze M4 and M5 into those 30 days; after expiry, upgrade to pay-as-you-go, and the main remaining cost is Foundry tokens |
| 7–8 hours a week isn't steady | No hard dates between milestones; progress only by the coverage table |
